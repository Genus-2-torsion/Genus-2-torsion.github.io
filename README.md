# Torsion of genus 2 Jacobians over ℚ — a census

Web site: **https://genus-2-torsion.github.io/** (served from this repository by GitHub Pages).

Which finite abelian groups occur as the rational torsion subgroup `J(ℚ)_tors` of the Jacobian `J`
of a genus 2 curve over ℚ?  The full list is unknown.  This census records every group for which a
curve is known, in three classes — **geometrically simple** Jacobians, Jacobians **split over ℚ**,
and Jacobians **simple over ℚ but split over ℚ̄** — re-verifies every curve with Magma (exact torsion
subgroup and a certificate of simplicity or splitness), links it to the LMFDB, and records for each
group whether infinitely many such Jacobians are known.  It is seeded with Tables 1 and 2 of

> J. S. Balakrishnan, F. Najman, A. Shnidman, A. V. Sutherland, *Rational torsion on simple genus
> two Jacobians*, [arXiv:2608.28543](https://arxiv.org/abs/2608.28543) (2026),

taken from the machine-readable tables of its certification repository
[AndrewVSutherland/Genus2Torsion](https://github.com/AndrewVSutherland/Genus2Torsion).  This repository holds

* the static web site (`index.html`, `group.html`, `curve.html`, `submit.html`, `about.html`, `assets/`);
* the data: one certificate per accepted curve in `data/curves/`, its Magma logs in `data/logs/`,
  rejected submissions in `data/rejected/`, the curated knowledge in `data/knowledge/` (copied source
  tables with provenance) and `pipeline/knowledge.py` (bibliography, "infinitely many?" records), and
  the generated `data/groups.json` / `data/curves.json` / `data/sources.json` the site reads;
* the verification pipeline in `pipeline/` (Python + Magma), which runs on the Mordell workstation.

## Submitting a curve

Open the [submission form](https://github.com/Genus-2-torsion/Genus-2-torsion.github.io/issues/new?template=submit-curve.yml)
(a GitHub issue), or add JSON files to `submissions/inbox/` in a pull request.  See
[submit.html](https://genus-2-torsion.github.io/submit.html) for the formats, including how to supply an
explicit map to an elliptic curve as a splitness certificate.  Submissions are pulled to Mordell,
verified with Magma, and the outcome is posted on the issue.

## Layout

```
index.html group.html curve.html submit.html about.html   the site (vanilla HTML/CSS/JS, no build step)
assets/                  style.css, app.js
data/curves/<id>.json    certificates (id = group key . letter, e.g. 2.2.12.a; 1.a for the trivial group)
data/logs/<id>.log       Magma log of the verification (+ <id>.conductor.log)
data/rejected/           rejected submissions with the reason
data/knowledge/sources/  verbatim copies of the source tables, with PROVENANCE.md
data/groups.json         generated by pipeline/build.py
data/curves.json         generated by pipeline/build.py
submissions/inbox/       queue; submissions/processed/ after verification
pipeline/                see pipeline/README.md
```

## Conventions

A curve is `y² + h(x)y = f(x)`, `deg f ≤ 6`, `deg h ≤ 3`, recorded up to isomorphism over ℚ.  Groups are
lists of invariant factors `[n₁, …, n_r]`, `[]` for the trivial group, listed in the paper's order.  Every
curve is placed in exactly one class, with a certificate recomputed from scratch (see the
[about page](https://genus-2-torsion.github.io/about.html)); without a certificate it is listed as
"verified · class not certified".  The "infinitely many?" column has three grades — `∞` (certified,
exact torsion), `∞ ⊇` (a family with torsion containing the group is proven), `?` (open) — with the
sources in `pipeline/knowledge.py`.
